## Воспроизводимые проверки

Команды выполняются из корня проекта. Для тестов и демо не нужны `.env`, рабочая БД, ключи или доступ к CoinMarketCap.

| Команда | Результат |
| --- | --- |
| `npm ci --ignore-scripts` | Установка зафиксированных зависимостей |
| `npm run test:coverage` | Сборка TypeScript; **135 тестов в восьми наборах — успешно** |
| `npm run check:openapi` | Локальные ссылки, параметры и девять операций — успешно |
| `npm run demo` | Авторизация, CRUD, фоновые обновления, история и сохранение данных — успешно |

Покрытие приложения без демонстрационного кода: **92,68% строк**, **92,58% инструкций**, **89,78% ветвлений**, **88,65% функций**. Счётчики родительского Jest-процесса не полностью учитывают код, выполняемый в дочерних процессах.

## Что покрыто

- Позитивные и негативные сценарии всех девяти операций; правильный, отсутствующий и неверный Bearer token.
- Проверка JSON, URL, идентификаторов, имён, пагинации и диапазонов дат; единый формат ошибок.
- Файловая SQLite: ограничения, транзакции, откат, история, каскадное удаление и сохранность после повторного открытия.
- Конкурентное добавление одного CMC ID: один внешний запрос, остальные ответы `409`, повторная попытка после неудачи.
- Блокировки SQLite: `503 DATABASE_BUSY` с `Retry-After: 1`, без синхронного ожидания освобождения блокировки.
- Ошибки и неполные ответы провайдера, таймауты, отмена, ограниченные повторы и пауза после превышения лимита.
- Отсутствующий CMC ID: `422 UNKNOWN_ASSET` без частичной записи; другие ответы HTTP 400 провайдера сохраняют статус внешней ошибки.
- Фоновые обновления без перекрытия, удаление во время синхронизации и остановка по SIGINT/SIGTERM, включая постоянные HTTP-соединения.

## Проверка с реальным CoinMarketCap

Отдельный сценарий использования с настоящими ключами проверил получение BTC/ETH/SOL, совпадение цены в API и истории, два фоновых обновления, удаление и повторное добавление, сохранность после полного перезапуска и отклонение неверного Bearer token. Выполнено 159 запросов к приложению и восемь к CoinMarketCap; провайдер сообщил расход семи кредитов.

После исправления обработки отсутствующего ID повторная проверка подтвердила `422`, отсутствие частичной записи, успешное добавление Bitcoin после ошибки и `401` с неверным Bearer token. Проверка вместе с диагностикой использовала три запроса к CoinMarketCap и один сообщённый кредит.

Для повторения ограниченной проверки со своими ключами доступна команда `npm run check:live`: не более одного запроса к CoinMarketCap, без фонового планировщика. Она добавляет Bitcoin или наблюдение в настроенную БД; для изоляции используйте `DB_PATH=./data/live-check.sqlite npm run check:live`.
