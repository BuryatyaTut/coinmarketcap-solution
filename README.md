# CoinMarketCap Price Tracker

Backend-сервис с защищённым REST API: список отслеживаемых криптовалют, последние сохранённые цены в USD и история наблюдений. Фоновая задача регулярно получает котировки CoinMarketCap и записывает их в SQLite.

## Стек

**Node.js 24.x** (проверено на 24.19.0, см. `.nvmrc`), TypeScript, Express, axios, SQLite без ORM, Jest + Supertest, OpenAPI 3.0.3.

Встроенный `node:sqlite` позволяет использовать raw SQL без дополнительного драйвера и соблюсти ограничение на библиотеки. Поэтому для запуска нужен Node 24; Node 18 не поддерживается. Прямые runtime-зависимости — Express и axios. Docker для запуска не требуется.

## Проверка без ключей

Из корня проекта:

```sh
node --version
npm ci --ignore-scripts
npm test
npm run check:openapi
npm run demo
```

Тесты сначала компилируют TypeScript, затем работают с временными файловыми SQLite-базами и подменённым провайдером. Демо показывает авторизацию, CRUD, фоновые обновления, историю и сохранение данных с синтетическими ценами. `.env`, ключи и доступ к CoinMarketCap для этих команд не нужны.

## Запуск с CoinMarketCap

1. Установите зависимости: `npm ci --ignore-scripts`.
2. Создайте `.env` по образцу `.env.example`, сохранив существующую конфигурацию, если она уже есть.
3. Запишите в `CMC_API_KEY` ключ своего аккаунта CoinMarketCap.
4. Для `APP_API_TOKEN` сгенерируйте **отдельный** ключ и сохраните его в `.env`:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Запустите сервер:

```sh
npm run build
npm start
```

Адрес по умолчанию — `http://127.0.0.1:3000`. Node загружает `.env`; переменные, уже заданные в окружении процесса, имеют приоритет. Каталог и схема БД создаются автоматически. Для остановки используйте Ctrl+C или SIGTERM.

Новая БД содержит пустой список монет. POST получает первую цену при добавлении. При запуске с непустым списком фоновая синхронизация начинается сразу, затем повторяется через заданный интервал после завершения предыдущего обновления.

### Конфигурация

| Переменная | По умолчанию / ограничение |
| --- | --- |
| `APP_API_TOKEN` | Обязателен; 16–512 символов без пробельных символов, отличается от ключа CMC |
| `CMC_API_KEY` | Обязателен для сервера; 1–512 символов без пробельных символов |
| `HOST` | `127.0.0.1`; также допустимы `0.0.0.0` и `::1` |
| `PORT` | `3000` |
| `DB_PATH` | `./data/prices.sqlite` |
| `SYNC_INTERVAL_MS` | `300000` — пять минут между завершением обновления и следующим запуском |
| `STALE_AFTER_MS` | `900000`; не меньше интервала обновления |
| `CMC_TIMEOUT_MS` | `5000` на попытку; при временной ошибке возможен один повтор |
| `SHUTDOWN_TIMEOUT_MS` | `10000` |

`.env`, БД, зависимости, сборка, покрытие и локальные отчёты исключены через `.gitignore`. В проект включены шаблон настроек и SQL-схема.

### Однократная проверка реального API

```sh
npm run check:live
```

Команда делает **не более одного запроса к CoinMarketCap**: получает BTC/USD, проверяет HTTP API и повторное открытие БД, затем останавливается. Планировщик отключён. Проверка **изменяет БД из `DB_PATH`**: добавляет Bitcoin или новое наблюдение к существующей записи. Для отдельной тестовой БД можно запустить `DB_PATH=./data/live-check.sqlite npm run check:live`. Локальные отчёты `docs/live-check-result.json` и `docs/live-response-sample.json` игнорируются Git.

Обычный `npm start` продолжает обновлять цены, пока сервер работает. При одном пакете монет и интервале пять минут это примерно 288 запросов в сутки, плюс добавления монет, перезапуски и повторы при ошибках. Выбирайте интервал с учётом лимитов аккаунта.

## Аутентификация

Все девять операций, включая OpenAPI, требуют заголовок:

```http
Authorization: Bearer <APP_API_TOKEN>
```

Общий middleware проверяет ключ до выполнения маршрута; отсутствующий или неверный ключ даёт `401 UNAUTHORIZED`. Все владельцы ключа имеют одинаковые права. `CMC_API_KEY` используется только сервером и не передаётся клиенту. Для удалённого доступа нужен HTTPS на уровне прокси. Подробнее: [аутентификация API](docs/authentication.md).

## API

Полный контракт и схемы ответов: [docs/openapi.json](docs/openapi.json). Файл можно импортировать в просмотрщик OpenAPI или получить через `GET /openapi.json` с авторизацией. Встроенной страницы Swagger UI нет.

| Метод | Путь | Операция |
| --- | --- | --- |
| POST | `/api/v1/cryptocurrencies` | Добавить монету по `cmcId`, сохранить первую цену |
| GET | `/api/v1/cryptocurrencies` | Список отслеживаемых монет |
| GET | `/api/v1/cryptocurrencies/{id}` | Одна запись |
| PATCH | `/api/v1/cryptocurrencies/{id}` | Изменить локальное отображаемое название |
| DELETE | `/api/v1/cryptocurrencies/{id}` | Удалить монету и её историю |
| GET | `/api/v1/cryptocurrencies/{id}/price` | Последняя сохранённая цена |
| GET | `/api/v1/cryptocurrencies/{id}/history` | История наблюдений |
| GET | `/api/v1/prices` | Последние цены отслеживаемых монет |
| GET | `/openapi.json` | OpenAPI-контракт |

В URL используется **локальный `id` из ответа POST**, который может отличаться от `cmcId` CoinMarketCap. Символ и начальное название приходят от провайдера; PATCH меняет только название.

Списки поддерживают `limit` от 1 до 100 (по умолчанию 50) и `offset` от 0. История принимает включительные границы `from` и `to`: ISO 8601 с секундами, часовым поясом и до трёх знаков дробной части секунд. Неизвестные поля, повторяющиеся параметры и некорректные значения отклоняются. Тела POST/PATCH должны быть JSON размером до 16 КБ.

### Пример использования

Задайте `APP_API_TOKEN` в окружении **терминала клиента**. Загрузка `.env` сервером не устанавливает переменные в другом терминале.

```sh
# Добавление Bitcoin обращается к CoinMarketCap.
curl -X POST http://127.0.0.1:3000/api/v1/cryptocurrencies \
  -H "Authorization: Bearer $APP_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"cmcId":1}'

# Здесь предполагается, что локальный id из ответа равен 1.
curl http://127.0.0.1:3000/api/v1/cryptocurrencies/1/price \
  -H "Authorization: Bearer $APP_API_TOKEN"

curl 'http://127.0.0.1:3000/api/v1/cryptocurrencies/1/history?limit=10' \
  -H "Authorization: Bearer $APP_API_TOKEN"

curl -X PATCH http://127.0.0.1:3000/api/v1/cryptocurrencies/1 \
  -H "Authorization: Bearer $APP_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"My Bitcoin"}'
```

Пример ответа о цене; значение иллюстративное:

```json
{
  "id": 7,
  "cryptocurrencyId": 1,
  "price": 80000.25,
  "currency": "USD",
  "observedAt": "2026-10-23T10:00:01.000Z",
  "sourceUpdatedAt": "2026-10-23T10:00:00.000Z",
  "stale": false
}
```

Время возвращается в UTC. `observedAt` — момент получения цены сервисом, `sourceUpdatedAt` — время котировки у провайдера. `stale` становится `true`, если возраст любого из этих значений превышает `STALE_AFTER_MS`. Чтение выполняется из БД без внешнего запроса, поэтому сохранённые цены доступны и при сбое CoinMarketCap.

### Ошибки

Единый формат: `{"error":{"code":"…","message":"…","requestId":"…"}}`.

| HTTP | Значение |
| --- | --- |
| 400 | Некорректные входные данные |
| 401 | Отсутствует правильный Bearer token |
| 404 | Запись или маршрут не найден |
| 409 `ALREADY_TRACKED` | Монета уже отслеживается или добавляется другим запросом |
| 413 / 415 | Слишком большое тело / неподдерживаемый формат |
| 422 `UNKNOWN_ASSET` | CoinMarketCap подтвердил отсутствие запрошенного CMC ID |
| 503 `DATABASE_BUSY` | SQLite занята; ответ содержит `Retry-After: 1` |
| 500 | Внутренняя ошибка без раскрытия деталей |
| 502 / 503 / 504 | Ошибка/лимит провайдера, отсутствие цены, остановка или таймаут; причина в `error.code` |

Из одновременных запросов на добавление одного `cmcId` только первый получает цену у провайдера; остальные получают `409`. Если первая попытка завершилась ошибкой, добавление можно повторить. Подтверждённый отсутствующий ID возвращает `422` без частичной записи в БД; прочие ошибки провайдера не маскируются под ошибку клиента.

## Решения и ограничения

- **История** накапливается с начала отслеживания, без загрузки прошлых периодов. Неизменившаяся котировка может стать новым наблюдением.
- **SQLite** хранит все монеты и цены в двух таблицах. Запросы параметризованы, связанные изменения атомарны, удаление каскадное. Запоздалый ответ синхронизации не восстанавливает удалённую запись.
- **Обновления** идут пакетами до 100 монет без перекрытия циклов. Есть таймаут, не более одного повтора при временной ошибке и пауза после 429 с учётом `Retry-After`.
- **Остановка** по SIGINT/SIGTERM прекращает приём запросов и фоновую работу, отменяет внешние обращения, завершает активные запросы и закрывает соединения и БД. Превышение срока остановки даёт ненулевой код выхода.
- **Масштаб** — один процесс. Защита от параллельного добавления и пауза после лимита хранятся в памяти только как служебное состояние. SQLite остаётся источником данных; несколько экземпляров приложения не координируются. SQL выполняется синхронно, но ожидание внешней блокировки БД отключено: запрос получает `503`, не задерживая event loop на время ожидания блокировки.
- **Точность** — JavaScript `number` и SQLite `REAL` для котировок; точная денежная арифметика не реализована.

Результаты проверок и их границы: [docs/validation.md](docs/validation.md). Для отчёта о покрытии выполните `npm run test:coverage`. Автотесты и демо не расходуют кредиты CoinMarketCap.
